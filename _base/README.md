# `_base/` — what every site shares

## `environment-update.yml`: the one environment

[`environment-update.yml`](environment-update.yml) is the environment the sites are to build in (QuantEcon/project-monorepo#77): what a build applies over the full image, `ghcr.io/quantecon/quantecon` (Python 3.13 and the `anaconda=2026.07` metapackage, the base every series' `environment.yml` names), with QuantEcon/actions' `setup-environment` (`environment-update:`). With one environment a pool lecture executes the same way in every site that lists it. The site-build workflow builds with it every site whose `site.yml` sets `environment: base`, intro and advanced so far; `dp` moves after its first shadow comparison.

- **One up-to-date baseline** (the owner's decisions of 2026-11-18 and -19). Every version is exact, for stability while the sites' builds are first developed, and is the newest release on 2026-11-19, except a package the `anaconda=2026.07` metapackage holds (at its version there, the base every series builds on), `jupyter-book` (the newest 1.x, until the engine switch), and a version a lecture asks for (`"prettytable<3.18"`: the newest it allows). The six series were brought to the same baseline upstream by 2026-11-20, one pull request each.
- **Where it moves the full image.** The build stack stays at the image's versions. `kaleido` goes from the image's 0.2.1 to 1.5.2, which needs a Chrome: since QuantEcon/actions#346 (2026-11-19) both images carry Chrome for Testing 158.0.8127.36 at `/opt/chrome`, with `BROWSER_PATH` set (QuantEcon/actions#85, QuantEcon/actions#342). sphinx, markdown-it-py and alabaster go back to what jupyter-book 1.x needs, as in every series' build.
- **A person changes a pin, after testing.** A workflow that watches for new releases of these packages and of the image is QuantEcon/project-monorepo#134. An entry without a version would not stay put: conda installs the pip list with `pip install -U`, so it would take the newest release on every build.
- **The lectures keep their install lines**, for readers running a notebook on Colab or at home. In a build a plain `!pip install` finds the package already here. An `--upgrade` line, or a `!conda install` of a package pinned here, replaces the pin for the rest of that build, since every lecture of a site runs in the same environment, so those lines were removed upstream by 2026-11-20. The three `!conda install … plotly-orca` lines went with them, so `plotly-orca` can leave the list too, in a pull request of its own.
- **`jax` is the CPU wheel.** A GPU build adds `jax[cuda13]==0.12.1` on top, the same version, which brings the CUDA plugin and the CUDA libraries it bundles (`nvidia-*` wheels, not pinned here). The GPU machine image holds no `anaconda` metapackage, so a GPU build needs that base as well; that is settled with the GPU leg. jax 0.11.1 hangs programming's `numpy_vs_numba_vs_jax`; 0.12.1 runs it, so the list moved from 0.11.0 to 0.12.1 (the owner's decision of 2026-11-19).

## Keeping it whole

[`tools/pool-check`](../tools/pool-check) turns a pull request's check red (`main` has no branch protection, so a red check is the signal) when a pool lecture's code cells install a package the file does not list, or a version limit in a pip install line does not allow the pinned version (`install-listed`; a conda install is matched by name), and when an entry is not pinned to one version, once (`environment`). It also counts the installs in executed cells that would replace a pin during a build (`--upgrade`, `-U`, a conda install), as information that falls to nothing as the upstream removals land; `tools/pool-check --installs` lists them.

When a refresh brings in a lecture that installs something new, the refresh pull request's pool-check goes red. Pin the package here **in a pull request of its own to `main`**, not on the refresh branch: `drift-check.yml` rebuilds `drift/refresh` from `main` on every run that still needs a refresh, so a commit pushed there is lost the next night. Once the pin has merged, the next scheduled run (or a manual run of `sync.yml`) rebuilds the refresh pull request on top of it, and its pool-check passes.
